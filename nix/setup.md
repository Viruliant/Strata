# Strata Nix Setup Guide

## Overview

This is the working setup on this machine as of 18 Nov 2026. It uses the
`min_changes` branch (HEAD `609fbc96e`). The Nix build provides a fully locked
Python 3.12 environment through uv2nix, and the CUDA engine is built for the
Tesla P100s.

The model was loaded and answered a test prompt through the OpenAI-compatible
API. The exact commands and observed results are also in
[`tested.md`](tested.md).

## Hardware

- Two Tesla P100-PCIE-16GB cards, compute capability 6.0 (Pascal).
- Driver 580.178.04; the Nix engine uses CUDA 12.
- System RAM: 31 GB. CPU: Intel i7-8700 (AVX2).
- Only GPU 0 is used. The Qwen3.6 engine cannot split one model across both
  cards; `--gpu 0,1` only changes visibility and `--parallel N` sets request
  slots. GPU 1 stays idle.

## Nix build system

The Python environment comes from `requirements.bak.txt` and `nix/uv.lock` via
uv2nix. `flake.nix` stays small; `package.nix` does the work.

| File | Purpose |
|------|---------|
| `flake.nix` | Declares `nixpkgs` and `flake-parts`; exposes packages and the dev shell |
| `package.nix` | Builds the uv2nix virtual environment, desktop app, and engines |
| `requirements.bak.txt` | **Editable source** for Python dependencies (repo root) |
| `nix/requirements.txt` | Generated by `uv pip compile` |
| `nix/pyproject.toml` | Generated metadata read by uv2nix |
| `nix/uv.lock` | Generated, fully pinned dependency versions |
| `nix/update-lock.sh` | Regenerates the three generated files |
| `nix/myCustomOverrides.nix` | Hook for overriding individual packages with nixpkgs versions |

The dev shell uses `inputsFrom = [ pkg.servePkg ]` to pull the virtual
environment into the shell.
There is no `python313Packages.pip` and no `PATH` shell hook. `python3` in
`nix develop` is the locked Python from `strata-env`.

To check the dev shell:

```bash
cd /home/ghost/Strata
nix develop --command bash -c 'command -v python3; python3 --version; python3 -c "import numpy; print(numpy.__version__)"'
```

Expected: `python3` under `/nix/store/...-strata-env/bin/python3`, version
`3.12.16`, and `numpy` `2.5.3`.

## Verified load and test procedure

### 1. Build

```bash
cd /home/ghost/Strata
nix build
nix build '.#servePkg'
nix build '.#engine-cuda'
ENGINE=$(readlink -f result)
echo "$ENGINE/bin/strata"
```

`nix build` alone builds the Tauri desktop app. The engine is the
`.#engine-cuda` output. `package.nix` pins `cudaArch = "60"` and passes
`-DSTRATA_EXPERIMENTAL_SM60=ON`, which the P100s require.

### 2. Write the server config

Use the engine path printed above:

```bash
mkdir -p /tmp/opencode
cat > /tmp/opencode/qwen36-min-changes.json <<EOF
{
 "exe": "$ENGINE/bin/strata",
 "args": [
  "--native",
  "/home/ghost/ntfs160gb/models/qwen36-UD-Q4_K_XL/Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf",
  "--max-context",
  "16384",
  "--prefill",
  "auto"
 ],
 "cwd": "/home/ghost/Strata",
 "tokenizer": "/home/1B62BC4D3C825DDF/packs/qwen36-ud-q4_k_xl/tokenizer",
 "model_name": "qwen3.6-35b-a3b-ud-q4_k_xl",
 "arch": "qwen35moe",
 "log": "/tmp/opencode/qwen36-min-changes.engine.log",
 "lib_dirs": [],
 "port": 8080,
 "cuda": 12,
 "gpu": 0,
 "parallel": 1,
 "mtp": false,
 "host": "127.0.0.1"
}
EOF
python3 -m json.tool /tmp/opencode/qwen36-min-changes.json >/dev/null && echo CONFIG_OK
```

### 3. Start the server

```bash
cd /home/ghost/Strata
nix develop --command env LD_LIBRARY_PATH=/run/opengl-driver/lib \
  python3 serve/server.py --engine strata \
  --config /tmp/opencode/qwen36-min-changes.json --port 8080
```

Leave this running. Loading takes about 70 seconds, then the server prints
`ready: http://127.0.0.1:8080/v1`. `LD_LIBRARY_PATH=/run/opengl-driver/lib` is
needed so the Nix-built engine finds the CUDA driver libraries instead of Nix
stub libraries.

### 4. Test

```bash
curl -sS http://127.0.0.1:8080/v1/models
curl -sS http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.6-35b-a3b-ud-q4_k_xl","messages":[{"role":"user","content":"Reply with exactly: STRATA_OK"}],"max_tokens":256,"temperature":0}'
```

A working reply has `"content": "STRATA_OK"` and `"finish_reason": "stop"`.
Do not set `max_tokens` as low as 32: the model reasons first and will run out
of tokens before answering.

Observed: model status `loaded`, 151 generated tokens, roughly 40–45 tokens/s,
GPU 0 around 15.7 GiB used, GPU 1 idle.

## Updating dependencies

1. Edit `requirements.bak.txt` at the repo root.
2. Run `./nix/update-lock.sh` with network access.
3. Rebuild with `nix build '.#servePkg'`.

## Troubleshooting

- `ModuleNotFoundError` for `serve`: run the server from the source directory
  as shown above. The `strata` launcher in the Nix store cannot import `serve`.
- Wrong CUDA libraries: keep `LD_LIBRARY_PATH=/run/opengl-driver/lib` in the
  server command.
- Engine path gone after `nix store gc`: run `nix build '.#engine-cuda'` again
  and update `exe` in the config with the new `readlink -f result` value.
- `strata launch` fails with `iq_embed_rows: invalid resource handle`: it picks
  the installed 0.1.60 component engine. Use the direct server command above,
  which points at the engine built from `package.nix`.
- Nix store is read-only: `setup.py` cannot write stamp files there. If a local
  engine build is needed, create a writable venv in the data directory and use
  it for that build.

## Limits

- Two server replicas would use one card each, but each copy needs about 19 GiB
  of pinned host RAM. This machine has 31 GiB total, so that does not fit.
- The old `setup.py` path with hardcoded `/nix/store/...` tools is superseded by
  the procedure above.
